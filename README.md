# 처음 만나는 Copilot Studio

개발 지식 없이 만드는 나의 첫 AI 에이전트.

[microsoft/easycopilotlab](https://github.com/microsoft/easycopilotlab)을 2026년 8월 화면 기준으로 다시 정리한 수강생용 교재입니다. 원본의 구성과 실습 흐름을 그대로 두고, 그 사이 바뀐 Copilot Studio 화면과 용어를 반영했습니다.

교재 보기: https://ltnalsxl.github.io/easycopilotlab/latest/

## 무엇이 달라졌나

**화면 변경 반영**

| 항목 | 이전 | 현재 |
|---|---|---|
| 홈 화면 | 표준 에이전트가 기본 | GitHub Copilot 하네스가 기본, 표준은 "기타 빌드 방식" 안 |
| 모델 선택 | 설정 화면 | 개요 페이지의 모델 섹션 |
| 토픽 노드 | 작업 호출 | 도구 추가 |
| 지식 원본 필터 | 지정된 원본만 사용 | 선택된 출처만 검색 |
| 커넥터 자격 증명 | 작성자가 제공한 | 제작자 제공 |
| 기본 모델 | GPT-4o | GPT-4.1 |

**사실관계 수정**

Microsoft Learn 공식 문서와 대조해 사실과 다른 부분을 고쳤습니다.

| 위치 | 이전 | 수정 |
|---|---|---|
| 과정 소개 | 품질은 지침의 품질로 결정된다 | 지침, 지식, 도구와 토픽의 설명, 오케스트레이션 설정의 조합으로 정해진다 |
| M6 | 오케스트레이터는 AI 모델이다 | 모델은 추론과 생성을, 오케스트레이터는 그 바깥의 진행을 맡는다 |
| M7 | 지침의 요소는 네 가지 | 다섯 가지. 맥락(Context)이 빠져 있었다 |
| M7 | 지침의 품질이 에이전트의 품질을 결정한다 | 지침은 안내이며 동작을 강제하지 않는다 |
| M9 | 토픽을 도구의 한 종류로 분류 | 공식 분류는 지침, 토픽, 도구, 지식. 토픽은 도구와 나란한 항목임을 표기 |

그 밖에 이전 개정에서 정리한 것들입니다.

- "Copilot Studio 라이트"는 존재하지 않는 제품명이라 삭제
- 커넥터 개수는 공식 표기에 수치가 없어 삭제
- Azure AI Search는 아직 프리뷰라 정식 지식 소스 목록에서 제외
- `utcNow()`는 시스템 변수가 아니라 Power Fx 함수
- "휴먼인더루프"를 공식 한국어 표기인 "인간 참여 제어"로 교체

**보완한 내용**

실습 중 막히기 쉬운 지점을 공식 문서에서 가져와 채웠습니다.

- M3에 에이전트 빌더 설명 추가. 선언형 에이전트가 무엇인지, 만드는 방법 세 가지(구성 / 설명 / 템플릿)
- M3에 자연어로 요청할 때 무엇을 함께 적으면 좋은지 안내. 특히 지식 파일을 붙일 계획이면 미리 밝혀 둘 것
- M4에 Power Platform 환경 설명 추가. 환경 유형, 역할, DLP 정책이 커넥터에 미치는 영향
- M5의 화면 안내를 왼쪽 메뉴와 에이전트 탭으로 나누고 활동, 평가, 분석 탭 추가
- M7에 지침에서 도구와 토픽을 부를 때 `/`로 삽입해야 하는 이유 추가
- M8에 색인 대기 안내 추가
- M9에 도구의 이름과 입출력 매개변수 이름도 선택에 영향을 준다는 내용 추가
- M12에 Outlook 메일 보내기 커넥터 실습 신설. 고정값과 에이전트가 채우는 값의 차이를 다룸
- M15를 선택 실습으로 표시하고 웹 접근이 막힌 조직을 위한 대체 방법 안내

## 실습 파일 수정

`files/` 아래 Word 문서 두 개를 고쳤습니다. 문서끼리 어긋나 있어 에이전트가 같은 질문에 다르게 답할 수 있는 상태였습니다.

**FAQ.docx**

`담당자정보.docx`에 존재하지 않는 팀 별칭 주소를 쓰고 있었습니다. 실제 담당자로 바꿨습니다.

| 항목 | 이전 | 수정 |
|---|---|---|
| 자격증 지원 | `hr@company.com` | 박교육 `park.kyoyuk@company.com` |
| 영문 재직증명서 | `hr@company.com` | 김인사 `kim.insa@company.com` |
| 주차 신청 | `gm@company.com` | 최총무 `choi.chongmu@company.com` |

담당 업무는 `담당자정보.docx`의 담당자별 상세 항목을 따랐습니다.

**휴가_근태_가이드.docx**

연차 표의 마지막 행이 규칙을 건너뛰고 있었습니다. 3년부터 2년마다 1일씩 늘어난다고 해 놓고 5~7년 17일 다음이 곧장 25일이었습니다. 7년차를 물으면 25일이라고 답할 수 있는 상태였습니다.

| | 이전 | 수정 |
|---|---|---|
| 7년 이상 부여 일수 | 최대 25일 | 18일 |
| 비고 | 상한선 25일 | 7년 18일, 9년 19일, 이후 2년마다 1일 추가. 상한 25일 |

`FAQ.docx`의 "3년 이상부터는 2년마다 1일씩 추가되어 최대 25일"과 이제 맞습니다.

나머지 세 파일(`담당자정보.docx`, `복리후생_안내.docx`, `경비처리_가이드.docx`)은 손대지 않았습니다. 다섯 파일 모두 병합 셀, 텍스트 상자, 이미지 안 텍스트가 없어 색인에 문제가 없습니다.

## 그 밖에

- 한글이 깨져 있던 개념도 3장을 다시 그렸습니다
- 사이드바에서 모듈을 고르면 해당 쪽만 나오는 방식으로 바꿨습니다. 좌우 방향키로도 넘어갑니다
- 실습이 여러 개인 모듈은 사이드바에 소제목이 펼쳐집니다
- GitHub Copilot 하네스가 아닌 표준 하네스 기준입니다
